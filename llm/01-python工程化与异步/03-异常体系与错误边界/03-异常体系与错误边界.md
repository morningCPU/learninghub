# 03-异常体系与错误边界  

## 作用  

1. 分层，划定边界，从而方便排错  
2. 保留原始异常链用于排查  

  

## 一、学什么  

> 1. 异常分层设计：业务异常(4xx)、基础设施异常(503)、编程错误(500)  
> 2. exception chaining 与 cause  

  

## 二、基础知识  

### 2.1 三类异常  

**(1) 业务异常**  

AppError  
4xx  
用户侧问题，用户可以理解，用户自己解决  
返回友好提示，普通日志，不告警  

**(2) 基础设施异常**  

InfraError  
503  
一些依赖的基础设施的异常，超时断连等  
重试、熔断、降级。日志标记依赖异常，按需告警  

**(3) 编程错误**  

BugError  
500  
代码错误  
强告警  

### 2.2 异常链  

**(1) 写法**  

```python  
try:  
    requests.get("xxx",timeout=1)  
except requests.exceptions.Timeout as e:  
    raise InfraError("下游服务调用超时") from e  
```

+ `from e` 设置新异常的 `__cause__ = e` 保留上游链条  
  

**(2) 访问原始异常**  

```python  
try:  
    ...  
except InfraError as err:  
    root_cause = err.__cause__  
    if isinstance(root_cause, requests.exceptions.Timeout):  
        print("根因：下游超时")  
```

**(3) 问题**  
**`raise from` 有什么用**  

用来建立异常因果链，给新异常绑定 `__cause__`,不写的话会导致原始异常堆栈丢失，无法定位底层原始错误  

  

## 三、实践  

**(1) 定义三层基础异常基类**  
需要都带上错误码和友好文案  

```python  
class BaseServiceError(Exception):  
    """所有自定义异常的父类"""  
    code: str  
    message: str  
  
    def __init__(self, code: str, message: str):  
        self.code = code  
        self.message = message  
        super().__init__(message)  
  
  
class AppError(BaseServiceError):  
    """业务异常：用户侧问题，4xx"""  
    pass  
  
  
class InfraError(BaseServiceError):  
    """基础设施异常：依赖故障，可重试，503"""  
    pass  
  
  
class BugError(BaseServiceError):  
    """程序bug：不该发生，500，强制告警"""  
    pass  
```

**(2) 边界异常分析**  
边界就是和外部交互的地方  
捕获原生异常，翻译成三层异常  

**http 请求封装函数**  

```python  
import requests  
  
def call_external_api(url: str):  
    try:  
        resp = requests.get(url, timeout=2)  
        resp.raise_for_status()  
        return resp.json()  
    except requests.exceptions.Timeout as e:  
        # 超时 → 基础设施异常，可以重试  
        raise InfraError(code="INFRA_TIMEOUT", message="下游接口调用超时") from e  
    except requests.exceptions.ConnectionError as e:  
        raise InfraError(code="INFRA_CONN_FAIL", message="无法连接下游服务") from e  
    except requests.exceptions.HTTPError as e:  
        # 如果下游返回4xx，属于业务侧问题，转AppError  
        if 400 <= e.response.status_code < 500:  
            raise AppError(code="APP_EXTERNAL_PARAM_ERR", message="下游提示参数非法") from e  
        raise InfraError(code="INFRA_DOWNSTREAM_ERR", message="下游服务返回异常") from e  
```

**参数校验边界**  

```python  
def parse_user_id(uid: str):  
    if not uid.isdigit():  
        # 校验失败：用户输入错，AppError  
        raise AppError(code="APP_INVALID_PARAM", message="用户ID必须是数字")  
    return int(uid)  
```

**编程错误场景**  

```python  
def get_username(info: dict | None):  
    if info is None:  
        # 按设计，这里info一定不能是None，出现就是代码bug  
        raise BugError(code="BUG_NONE_REF", message="info意外为None，空引用")  
    return info["name"]  
```

**(3) 设置全局唯一异常出口**  
将所有异常汇聚到这里，只在这里决定返回给前端什么，日志怎么记录  

**统一响应体格式**  

```json  
{  
    "code": "APP_INVALID_PARAM",  
    "message": "用户ID必须是数字",  
    "request_id": "req-xxxx-xxxx"  
}  
```

**全局捕获逻辑伪代码**  

```python  
def global_exception_handler(exc: Exception, request_id: str):  
    logger_kwargs = {"request_id": request_id}  
    if isinstance(exc, AppError):  
        logger.warning(f"业务异常: {exc.code} {exc.message}", exc_info=True, extra=logger_kwargs)  
        return 422, {"code": exc.code, "message": exc.message, "request_id": request_id}  
    elif isinstance(exc, InfraError):  
        logger.error(f"依赖异常: {exc.code} {exc.message}", exc_info=True, extra=logger_kwargs)  
        return 503, {"code": exc.code, "message": exc.message, "request_id": request_id}  
    else:  
        # BugError、以及所有漏捕获的原生异常全部进这里，500  
        logger.critical(f"程序异常500", exc_info=True, extra=logger_kwargs)  
        # 对外隐藏真实细节，统一文案  
        return 500, {"code": "SERVER_INTERNAL_ERROR", "message": "服务内部异常", "request_id": request_id}  
```

  

## 四、问题  

**1. 什么时候该抛异常，什么时候该返回错误值**  

核心就是判断这个错误是不是调用方正常业务流程里面预期会频繁发生的  
如果是非正常、需要中断流程、向上传递、统一日志 / 告警的失败，抛异常；如果是业务上很常见的分支状态，调用方就近处理，用返回错误值。  

**2. raise from 有什么用，不写会丢什么信息**  

用来设置新异常的`__cause__`从而保留上游异常信息，构建异常因果链。不写 from，`__cause__` 为空，底层原始异常类型、堆栈丢失，无法知道源头错误  

**3. 线上一个 500 你怎么快速判断是用户输入问题还是代码 bug**  

规范体系下，用户输入问题不会产生 500；500 代表代码缺陷或者兜底未捕获异常
