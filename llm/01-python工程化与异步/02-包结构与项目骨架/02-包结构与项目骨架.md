# 02-包结构与项目骨架  

## 作用  

1.让改代码的时候不会import错版本  
2.换机器时不会少文件  
3.发wheel时不会缺元数据  
4.不发生依赖冲突  

## 一、学什么  

> 1. src布局  
> 2. pyproject.toml（PEP 621）  
> 3. 命名空间  
> 4. `__init__.py`的导出约定  

  

## 二、基础知识  

### 2.1 src布局  

```text  
my-lib/  
|-- pyproject.toml  
|-- README.md  
|-- tests/  
	 |-- test_xxx.py  
|-- src/  
	 |-- mylib/  
	 	  |-- __init__.py  
	 	  |-- subpkg1/  
	 	  |-- ...  
```

+ src目录本身不是包，不要放 `__init__.py`  
+ 所有要分发，对外import的代码全部放到src/下面  
  

**为什么要用src布局，而不是直接将mylib放到根目录(flat布局)**  

1. python默认把当前工作目录`.`放进`sys.path`  
   扁平布局时，在项目根直接import mylib,拿的是磁盘上的源码文件而不是打包后的安装版本  
2. src布局强制必须先安装(pip install -e .)才能import,这让测试、开发时验证的就是和wheel一模一样的导入视图  
3. 避免项目中其他文件意外打包  
4. 将import路径和仓库目录解耦  

### 2.2 PEP621  

`pyproject.toml` 标准元数据  

```toml  
[build-system] #指定构建后端  
requires = ["setuptools>=61.0"]  
build-backend = "setuptools.build_meta"  
  
[project] #标准元数据  
name = "mylib"  
version = "0.1.0"  
# 主依赖，一定安装  
dependencies = [  
    "numpy>=1.24"  
]  
# 可选依赖 pip install mylib[torch,dev] 这种方式进行安装  
[project.optional-dependencies]  
dev = [  
    "pytest>=7.0",  
    "ruff",  
    "build"  
]  
torch = [  
    "torch>=2.2"  
]  
  
[tool.setuptools.packages.find]  
where = ["src"]  # 告诉setuptools去src下找包  
```

### 2.3 `__init__.py`导出约定  

常规包、命名空间包  

**(1) 常规包**  
只要目录中有 `__init__.py` ，python就把这个文件夹识别成常规包  
**空的`__init__.py`**  
导入需要写完整路径  

```python  
# 必须写完整路径  
from mylib.subpkg1.api import func1  
from mylib.subpkg2.api import ClassA  
```

**自己写`__init__.py`重导出**  
对于  

```text  
src/mylib/  
├── __init__.py  
├── subpkg1/  
│   ├── __init__.py  
│   └── api.py   # def func1(): ...  
└── subpkg2/  
    ├── __init__.py  
    └── api.py   # class ClassA: ...  
```

对于 `__init__.py` 可以这样写  

```python  
# 从内部子模块导入，重导出到包顶层  
from .subpkg1.api import func1  
from .subpkg2.api import ClassA  
  
# __all__ 控制 from mylib import * 会导入哪些名字  
__all__ = ["func1", "ClassA"]  
```

使用  

```python  
from mylib import func1, ClassA  
# 不需要关心 subpkg1 / subpkg2 / api.py 这些内部细节！  
```

+ `__all__`：**只影响**`from xxx import \*`，不影响显式 `from mylib import func1`；  
  

**(2) 命名空间包PEP420**  
父目录没有`__init__.py`  

  

## 三、实践  

**(1) 建立目录**  

```text  
mylib/  
├── pyproject.toml  
├── tests/  
│   └── test_import.py  
└── src/  
    └── mylib/  
        ├── __init__.py  
        ├── subpkg1/  
        │   └── __init__.py  
        ├── subpkg2/  
        │   └── __init__.py  
        ├── subpkg3/  
        │   └── __init__.py  
        ├── subpkg4/  
        │   └── __init__.py  
        └── subpkg5/  
            └── __init__.py  
```

**(2) 开发可编辑安装**  

`pip install -e ".[dev]"`  

**(3) 构建**  

`python -m build`  
得到whl文件  

**(4) 新环境安装使用**  

`pip install dist/mylib.whl`  

  

## 四、问题  

**(1) 为什么要用 src 布局而不是直接在根目录放包**  

1. 防止直接使用了mylib而不是使用的打包之后的  
2. 保证了一定要 `pip install -e .` 之后才可以使用，保证开发环境和使用环境的一致  
3. 避免打包了其他文件  
4. 将import路径与代码目录解耦  

**(2) 包被别人 import 之后循环依赖怎么解**  

1. 重构，把都依赖的公共逻辑抽取成另外一个模块  
2. 延迟导入  
3. 改用模块导入  

**(3) 依赖冲突时怎么定位是哪个包锁死了版本**  

查看依赖树 `pipdeptree -p requests`
