## 二、做什么  

### 2.1 知识学习  

读《Java核心技术 卷1》第 7 章"异常、断言和日志" + JavaGuide "Java 异常" 一节  

**1. 什么是异常**  
异常是程序运行的过程中发生的不正常情况  
java使用面向对象方式处理异常，发生错误时JVM或代码会创建异常对象并抛出  
**2. java异常类层次结构**  

```text  
java.lang.Throwable  
|-- Error 错误：系统级严重故障，程序无法处理，不捕获  
	|-- OutOfMemoryError、StackOverflowError  
|-- Exception 异常：程序层面可捕获处理  
	|-- RuntimeException 运行时异常，非受检异常(Unchecked Exception)  
		|-- NullPointerException、ArrayIndexOutofBounds、  
			ClassCastException、ArithmeticException  
	|-- 其他 受检异常(Checked Exception)  
		|-- IOException、SQLException  
```

**(1) 受检异常**  
编译器强制要求要么`try-catch`捕获，要么`throws`抛出  
一般是外部资源问题  
**(2) 非受检异常**  
不强制要求捕获  
一般是代码BUG  

**3. 异常的抛出与捕获**  
**(1) throw**  
主动抛出异常，写在方法体中  

```java  
if(age < 0){  
    throw new IllegalArgumentException("年龄不能为负数")  
}  
```

+ 手动创建异常对象并抛出  
+ 抛出受检异常时，方法必须用throws声明  
+ 只能抛出一个对象  
  

**(2) throws**  

```java  
public void readFile() throws IOException{  
    // IOException code  
}  
```

+ 说明本方法不处理这些异常，交给调用者处理  
+ 只是声明异常类，不能抛对象  
+ 多个异常之间逗号隔开  
+ 子类throws不能比父类范围更大  
  

**(3) try-catch**  

```java  
try{  
    //可能发生异常的业务代码  
}catch (NullPointerException e){  
    //捕获后处理  
}catch (IOException e){  
    //捕获后处理  
}  
  
//合并写法  
try{  
      
}catch(NullPointerException | IOException e){  
      
}  
```

+ 多个catch范围要从小到大  
+ e 默认为final，不可重新赋值  
  

**(4) finally**  

```java  
FileInputStream fis = null;  
try{  
    fis = new FileInputStream("a.txt");  
}catch(IOException e){  
    e.printStackTrace();  
}finally{  
    if(fis!=null)fis.close();  
}  
```

无论try正常结束还是触发catch捕获异常，finally一定会执行  
唯一finally不执行的情况就是在前面执行了`System.exit()`，JVM会直接退出  

+ 在try里面return会先执行finally再return  
+ finally内部如果写return会覆盖try/catch的return  
+ finally中抛出异常，会覆盖原有的异常  
+ 禁止finally写return和throw  
  

**(5) try-with-resources**  

```java  
try(FileInputStream fis = new FileInputStream("test.txt"));  
	BufferedReader br = new BufferedReader(new InputStreamReader(fis)){  
    String line = br.readLine();  
    }catch(IOException e){  
        e.printStackTrace();  
    }  
```

+ 资源会自动关闭，在try结束时自动执行  
+ 关闭时如果也抛出异常，原异常不会丢失，被suppressed捕获  
+ 建议用这个替换`try-catch-finally`  
  

**4. 异常对象的常用方法**  

```java  
e.getMessage(); //返回异常简短描述字符串  
e.toString(); //异常类名 + message  
e.printStackTrace(); //打印堆栈轨迹  
e.getCause(); //获取根原因异常  
e.getSuppressed(); //获取被抑制的异常  
```

**5. 自定义异常**  
区分业务错误和JDK原生异常  

+ 自定义受检异常：继承Exception  
+ 自定义非受检异常：继承RuntimeException  
  
```java  
public class UserNotExistException extends RuntimeException{  
    public UserNotExistException(){  
        super();  
    }  
    public UserNotExistException(String msg){  
        super(msg);  
    }  
    public UserNotExistException(String msg,Throwable cause){  
        super(msg,cause);  
    }  
}  
```

+ 提供无参，带消息，带消息和根因这几个构造器，方便异常包装  
+ 业务异常优先使用RuntimeException，减少大量throws污染方法签名  
+ 异常信息带上业务上下文方便排查错误  
  

**6. 异常使用最佳实践**  
(1) 不要捕获Throwable/Exception，范围过大，容易吞Error，会有意想不到的异常  
(2) 不要用空catch块，这会让线上不知道哪里出错了  
(3) 不要用异常做业务流程控制，异常创建和栈信息的开销大  
(4) 捕获尽可能精准  
(5) 关闭资源优先用try-with-resources  
(6) 日志记录完整堆栈  
(7) 不要在finally抛出异常  
(8) 受检异常不要滥用  

**7. assert断言**  
用于开发测试阶段验证内部不变量  

```  
assert 条件;  
assert 条件 : 错误信息  
```

如果条件为false，抛出 AssertionError （Error,不可捕获）  
默认JVM禁用断言，启动参数 -ea开启,-da关闭  

**8. java日志**  
日志级别  
severe,warning,info,config,fine,finer,finest  
原生JUL实际项目很少用，生产一般使用SLF4J+Logback/Log4j2  

### 2.2 代码实现  

**1. finally中的return**  

```java  
public class ReturnTest {  
    public int re(){  
        try{  
            return 1;  
        }finally {  
            return 2;  
        }  
    }  
}  
//将会返回2  
```

**2. 自定义异常**  

自定义 `BizException extends RuntimeException`，在练习代码中抛出，在 main 中统一捕获并 `printStackTrace()`。  

```java  
//BizException.java  
package com.morning;  
  
public class BizException extends RuntimeException{  
    public BizException() {  
        super();  
    }  
  
    public BizException(String message) {  
        super(message);  
    }  
  
    public BizException(String message, Throwable cause) {  
        super(message, cause);  
    }  
}  
  
//ReturnTest.java  
package com.morning;  
  
public class ReturnTest {  
    public int re(){  
        try{  
            return 1;  
        }finally {  
            return 2;  
        }  
    }  
  
    public void diy() throws BizException{  
        throw new BizException("biz");  
    }  
}  
  
//App.java  
public class App {  
    public static void main(String[] args) {  
        ReturnTest r = new ReturnTest();  
        System.out.println(r.re());  
  
        try{  
            r.diy();  
        }catch (BizException e){  
            System.out.println(e.getMessage());  
        }  
    }  
}  
  
//2  
//biz  
```

  

## 三、实践  

**1. 画异常树并各举 3 个受检/非受检例子**  

```java  
Throwable  
|-- Error  
	|-- OutOfMemoryError、StackOverflowError  
|-- Exception  
	|-- RuntimeException  
		|-- NullPointerException、ArrayIndexOutofBounds、  
			ClassCastException、ArithmeticException  
	|- others  
		|- IOException、SQLException  
```

**2. finally 与 return 的执行顺序及 2 个例外情况**  

会先执行finally再执行return  
如果在finally中写了return的话，会覆盖外面的return  
例外情况：直接System.exit()将JVM停止，或者JVM崩溃/强行终止  

  

## 四、问题  

**1. 受检异常和非受检异常的区别**  

受检异常一定要抛出或进行处理  
非受检异常不强制要求  

**2. finally 中的 return 会覆盖 try 的 return 吗**  

会  

**3. try-with-resources 的原理**  

资源类要实现AutoCloseable接口  
这是编译期语法糖，javac编译后会自动生成try-finally+相应的close()调用
