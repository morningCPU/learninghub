## 二、做什么  
  
### 2.1 基础知识学习  
  
读《Java核心技术 卷1》第 8 章"泛型程序设计" + JavaGuide "泛型" 一节  
  
**1. 泛型的本质**  
参数化类型，把类型当做参数传递，编译器类型检查，避免大量类型转换，代码复用  
泛型只在编译期有效，运行时会擦除  
  
**2. 泛型的好处**  
  
+ 编译期类型检查，类型不对直接编译失败  
+ 省去强制类型转换，代码更简洁  
+ 实现代码复用，支持多种类型  
  
**3. 基础语法**  
**(1) 泛型类**  
  
```java  
public class Pair<T>{  
    private T first;  
    private T second;  
    public Pair(T first,T second){  
        this.first = first;  
        this.second = second;  
    }  
    public T getFirst(){return first;}  
    public void setFirst(T first){this.first = first;}  
}  
//使用  
Pair<String> pair = new Pair<>("A","B");  
```  
  
**类型参数命名习惯**：  
  
+ T (Type) : 任意类型  
+ E (Element) : 集合元素  
+ K (Key) / V (Value) : 键值对  
+ R (Return) : 返回值类型  
  
**(2) 泛型接口**  
  
```java  
public interface Generator<T>{  
    T next();  
}  
  
//实现类可以指定类型，也可以继续保留泛型  
// 类型固定为 String  
class StringGenerator implements Generator<String> {  
    @Override  
    public String next() { return "test"; }  
}  
// 类声明带上<T>，implements Generator<T>，继续保留泛型  
class GenericGenerator<T> implements Generator<T> {  
    @Override  
    public T next() {  
        // 这里只是示例，实际需要有办法生成T对象  
        return null;  
    }  
}  
```  
  
**(3) 泛型方法**  
泛型方法独立于类的泛型参数  
方法自己定义类型参数，不管类是不是泛型类  
  
```java  
public static <T> T getMiddle(T... a){  
    return a[a.length/2];  
}  
// 调用  
String mid = getMiddle("A","B");  
```  
  
**4. 类型擦除**  
Java泛型使用类型擦除实现，不是真正的模版  
(1) 编译阶段：编译器检查泛型类型，之后擦除所有类型参数  
(2) 擦除规则：  
     无边界`<T>` 擦除为Object  
     有上界`<T extends Comparable>` 擦除为上界类型  
  
(3) 编译器自动插入必要的强制类型转换和桥方法  
  
```java  
//示例  
Pair<String> pair = new Pair<>();  
//编译后字节码里，Pair 变成 Pair<Object>  
String s = pair.getFirst();  
//变为 String s = (String)pair.getFirst();  
```  
  
**类型擦除带来的重要结论**  
(1) 类型泛型不能实例化对象  
new T() 编译错误，擦除后是 Object T()，并不是想要的对象  
(2) 不能用instanceof判断泛型类型  
`obj instanceof Pair<String>`报错  
运行时没有String信息，只能写`obj instanceof Pair<?>`  
(3) 泛型数组不能直接创建  
new T[10]不行  
可以用`Array.newInstance()`反射创建  
(4) 泛型类不共享Class对象  
`Pair<String>.class == Pair<Integer>.class //true`  
运行时是同一个Class，但是编译期不同  
(5) 静态方法不能使用类的泛型参数  
静态属于类，泛型参数是示例层面的，擦除冲突  
静态方法想要泛型，只能定义泛型方法  
  
> C++模版 : 每个示例化类型都会生成一份独立的代码  
> Java泛型 : 只生成一份代码，靠擦除和强转实现  
  
**5. 限定类型变量**  
extend  
`<T extend 类型>` ： 上界限定，T只能是该类型后它的子类  
可以有多个边界 `<T extends A & B & C>`  
第一个可以是类，后面只能是接口，类必须写在最前面  
擦除时，擦到第一个边界类型  
  
+ 没有下界限定  
  
**6. 通配符**  
类型参数T是确定类型，通配符?代表未知类型，用于变量声明、参数  
  
```text  
? 无界通配符 ： Pair<?>  
? extends T 上界通配符 ： 未知类型是T或T的子类(读)  
? super T 下界通配符 ： 未知类型是T或T父类(写)  
```  
  
**(1) 无界通配符**  
`Pair<?>`  
可以读取，读到只能是Object  
不能写，除了null  
**(2) 上界通配符**  
`List<? extends Animal>`  
可以读得到Animal  
不能写，除了null  
**(3) 下界通配符**  
`List<? super Dog>`  
可以写  
获取元素只能获取到Object  
  
**不能同时绑定上界和下界**  
  
**PECS原则**  
Producer Extends,Consumer Super  
生产者只能被读取，消费者只能被写入  
  
**7. 泛型的继承与子类型**  
`Pair<String>`不是`Pair<Object>` 的子类  
`Pair<String>`是`Pair<?>`的子类  
  
**8. 桥方法**  
类型擦除后，子类泛型方法签名和父类不一致，编译器自动生成桥方法保证多态  
  
```java  
class Pair<T>{  
    public void setFirst(T t){}  
}  
class StringPair extends Pair<String>{  
    @Override  
    public void setFirst(String s){}  
}  
//擦除后父类变为setFirst(Object)  
//子类方法是setFirst(String),签名不一致  
//编译器自动生成桥方法  
public void setFirst(Object o){  
    setFirst((String) o);  
}  
```  
  
桥方法保证多态调用，复杂强制类型转换  
反射看到的方法会包含桥方法，可以用`isBridge()`判断  
  
**9. 泛型的限制**  
  
+ 不能用基本类型实例化泛型  
+ 不能创建泛型实例  
+ 不能创建泛型数组  
+ 泛型类不能直接继承/实现Exception  
+ 不能重载泛型擦除后签名一样的方法  
+ 静态变量不能是类的泛型类型  
+ equals、hashCode等Object方法不受泛型影响  
  
### 2.2 证明擦除  
  
```java  
System.out.println(  
    new ArrayList<String>().getClass() == new ArrayList<Integer>().getClass()  
);  
//true  
```  
  
### 2.3 擦除的后果  
  
```java  
List<String> list = new ArrayList<>();  
list.getClass().getMethod("add", Object.class).invoke(list, 123);  
```  
  
反射能往 `List<String>` 里塞进 Integer——编译期安全、运行期裸奔  
  
  
  
## 三、实践  
  
**1. 证明"泛型被擦除"并说出 3 个擦除后果**  
  
```java  
System.out.println(  
    new ArrayList<String>().getClass() == new ArrayList<Integer>().getClass()  
);  
//true  
```  
  
**擦除后果**：  
  
+ 运行时丢失泛型类型信息  
+ 不能直接new T()  
+ 泛型不能用于方法重载  
  
**2. 默写 PECS 并各举一例**  
  
PECS：Producer Extends,Consumer Super  
  
```java  
//生产者：从src读取元素，不写  
public static <T> T getFirst(List<? extends T> src){  
    return src.get(0);  
}  
  
//消费者：向dest中写元素，不读  
public static <T> void addItem(List<? super T> dest,T item){  
    dest.add(item);  
}  
  
//完整例子  
public static <T> void copy(List<? extends T> src,List<? super T> dest){  
    for(T t : src){  
        dest.add(t);  
    }  
}  
```  
  
  
  
## 四、问题  
  
**1. Java 的泛型是伪泛型吗,为什么**  
  
是，因为是用类型擦除实现的，最后对不同的类型只是一份代码，而不是像C++一样多份代码  
  
**2. ? extends T 和 ? super T的区别**  
  
extends确定上界，用于读  
super确定下界，用于写  
  
**3. 泛型擦除带来了哪些问题**  
  
- 运行时丢失泛型类型信息  
- 不能直接new T()  
- 泛型不能用于方法重载
