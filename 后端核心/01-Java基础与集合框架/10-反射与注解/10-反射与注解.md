## 二、做什么  
  
### 2.1 基础知识  
  
**1. 反射的作用**  
反射允许程序在运行时，拿到一个类的全部信息(类名、构造器、方法、字段)，并且实例化对象、调用方法、读写成员变量，哪怕编译期不知道这个类是谁  
**2. 基础概念**  
**(1) 什么是反射**  
正常编码(正向):  
`new User()` 编译期就知道User类，直接创建对象  
反射(反向):  
先拿到Class对象，再用Class对象去创建实例、调用方法。编译期不知道类，运行时才加载并解析类信息  
**(2) Class类**  
`java.lang.Class`  
每一个被JVM加载的类，在内存里都有唯一对应的Class对象  
  
```java  
//获取Class对象的3种方式  
//1. 类名.class (静态获取，不会触发静态代码块执行)  
Class<User> clazz = User.class;  
  
//2. 对象.getClass() （已有对象时获取）  
User user = new User();  
Class<? extends User> clazz2 = user.getClass();  
  
//3. Class.forName("全类名") (最常用)  
//会加载类，执行静态代码块  
Class<?> clazz3 = Class.forName("com.xxx.User");  
```  
  
+ 基本类型也有Class对象：int.class  
+ 包装类 `Integer.TYPE` 等价于 `int.class`  
  
**3. 类的组件**  
Constructor、Method、Field  
这三个类都在`java.lang.reflect`包  
1.`Constructor`:构造方法，用来创建对象  
2.`Method`:成员方法，用来调用方法  
3.`Field`:成员变量，用来读取/修改属性值  
**两组API**  
  
```text  
getXXX() : 获取public (包括父类public)  
getDeclaredXXX() : 获取本类中所有(所有访问类型，但是不包含父类)  
```  
  
**(1) Constructor**  
实例化对象  
  
```java  
//获取无参构造  
Constructor<User> con = clazz.getDeclaredConstructor();  
//暴力访问，private构造器必须开启  
con.setAccessible(true);  
User obj = con.newInstance();  
```  
  
**(2) Field**  
读写成员变量  
  
```java  
Field nameField = clazz.getDeclaredField("name");  
//暴力破解，关闭访问权限检查  
nameField.setAccessible(true);  
nameField.set(obj,"张三");  
String name = (String) nameField.get(obj);  
//对静态字段:get(null),set(null,value)  
```  
  
**(3) Method**  
调用方法  
  
```java  
Method sayMethod = calzz.getDeclaredMethod("say",String.class);  
sayMethod.setAccessible(true);  
Object res = sayMethod.invoke(obj,"hello");  
```  
  
**(4) setAccessible**  
不是修改权限，只是关闭Java语言访问检查  
只对当前这个反射对象起作用  
private成员必须加  
  
**4. 反射常用API**  
  
```java  
//获取反射对象  
Class<?> clazz = Class.forName("com.xxx.User");  
  
//获取类名  
clazz.getName(); //获取全类名  
clazz.getSimpleName(); //获取简单类名  
  
//获取父类  
clazz.getSuperclass();  
  
//获取实现接口  
clazz.getInterfaces();  
```  
  
**5. 反射的优缺点**  
**(1)优点**  
  
+ 动态  
  运行时才确定操作哪个类，适合框架  
  
+ 可以访问私有成员  
  
**(2)缺点**  
  
+ 性能低  
  反射绕过编译期优化，JVM很难做内联、优化  
  性能损耗来自类型解析、权限检查  
  可以通过 1.缓存Class、Method、Field对象；2.使用MethodHandle 进行优化  
+ 破坏封装  
  可以暴力访问私有元素  
+ 编译期无法校验  
+ 存在安全问题  
  安全管理器下受限  
  
**6. 反射相关异常**  
  
```   
ClassNotFoundException : Class.forName找不到类  
NotSuchMethodException : 找不到对应构造/方法  
NotSuchFieldException : 找不到字段  
IllegalAccessException : 权限不足  
InstantiationException : 抽象类/接口无法实例化  
InvocationTargetException : 调用方法本身抛出异常  
```  
  
**2.2 反射Demo**  
  
```java  
package com.morning;  
  
import java.lang.reflect.Constructor;  
import java.lang.reflect.Field;  
import java.lang.reflect.Method;  
  
/**  
 * Hello world!  
 */  
public class App {  
    public static void main(String[] args) throws Exception{  
        Class<?> clazz = Class.forName("com.morning.User");  
        Constructor<?> con = clazz.getDeclaredConstructor(String.class);  
        con.setAccessible(true);  
        User obj = (User) con.newInstance("morning");  
  
        Field nameField = clazz.getDeclaredField("name");  
        nameField.setAccessible(true);  
        nameField.set(obj,"tom");  
        System.out.println(nameField.get(obj));  
  
        Method sayHelloMethod = clazz.getDeclaredMethod("sayHello");  
        sayHelloMethod.setAccessible(true);  
        sayHelloMethod.invoke(obj);  
    }  
}  
```  
  
**2.3 反射慢的原因**  
  
动态查找方法、安全检查、无法 JIT 内联  
  
### 2.4 典型应用  
  
Spring IOC 依赖注入、AOP 动态代理、MyBatis 结果映射、JUnit 测试发现  
  
  
  
## 三、实践  
  
**1. 写出反射调用私有方法的代码**  
  
```java  
public class App {  
    public static void main(String[] args) throws Exception{  
        Class<?> clazz = Class.forName("com.morning.User");  
        Constructor<?> con = clazz.getDeclaredConstructor(String.class);  
        con.setAccessible(true);  
        User obj = (User) con.newInstance("morning");  
          
        Method sayHelloMethod = clazz.getDeclaredMethod("sayHello");  
        sayHelloMethod.setAccessible(true);  
        sayHelloMethod.invoke(obj);  
    }  
}  
```  
  
**2. 讲出 Spring 中至少 3 处反射应用**  
  
1. **IOC 容器创建 Bean**  
   `Class.forName` 加载类，`getDeclaredConstructor().newInstance()` 反射实例化。  
2. **依赖注入 DI**  
   `@Autowired` 通过反射拿到 `Field`/`Method`/`Constructor`，`setAccessible(true)` 后 `set`/`invoke` 注入依赖。  
3. **AOP 动态代理**  
   JDK 动态代理的 `InvocationHandler.invoke` 里用 `Method.invoke(target, args)` 反射调用原方法，前后织入切面。  
4. **注解解析**  
   `getAnnotation`/`isAnnotationPresent` 反射读取 `@Controller`、`@RequestMapping` 等，是 Spring MVC 路由映射的基础。  
  
  
  
## 四、问题  
  
**1. 反射的优缺点**  
  
**(1)优点**  
  
- 动态  
  运行时才确定操作哪个类，适合框架  
- 可以访问私有成员  
  
**(2)缺点**  
  
- 性能低  
  反射绕过编译期优化，JVM很难做内联、优化  
  性能损耗来自类型解析、权限检查  
  可以通过 1.缓存Class、Method、Field对象；2.使用MethodHandle 进行优化  
- 破坏封装  
  可以暴力访问私有元素  
- 编译期无法校验  
- 存在安全问题  
  安全管理器下受限  
  
**2. 注解是怎么生效的（运行时反射 vs 编译期 APT）**  
  
注解本身只是元数据，不会自己执行，**必须有人去读它**。读的时机有两种：  
  
1. **运行时反射**：注解用 `@Retention(RUNTIME)` 保留到运行时，框架用 `Class.getAnnotation()` 等反射 API 读取，再执行逻辑（如 Spring 的 `@Component` 扫描、`@Autowired` 注入）。灵活但有反射开销。  
2. **编译期 APT**：`javac` 编译时调用注解处理器，读取 `SOURCE` 级注解，**直接生成新代码**（如 Lombok 生成 getter/setter）。零运行时开销，编译期就能报错，但不灵活。  
  
**3. Spring 的 Bean 是怎么被扫描和创建的**  
  
Spring Bean 的扫描和创建分两个阶段：  
  
**扫描阶段**：`@ComponentScan` 触发 `ClassPathBeanDefinitionScanner`，遍历指定包下的 `.class`，用**反射读注解**判断是否带 `@Component`（`@Service`/`@Controller` 因元注解也算），通过后解析成 `BeanDefinition` 注册到 `BeanFactory`。这一步只登记"图纸"，不创建对象。  
  
**创建阶段**：容器调用 `getBean` 时，`AbstractAutowireCapableBeanFactory.doCreateBean` 依次做：  
  
1. **实例化**：反射 `getDeclaredConstructor().newInstance()` 造原始对象  
2. **属性填充**：反射 `setAccessible` + `set` 完成 `@Autowired` 注入  
3. **初始化**：执行 `@PostConstruct`、`InitializingBean`，并由 `BeanPostProcessor` 生成 **AOP 代理**  
4. **入缓存**：单例放进 `singletonObjects`  
  
整个过程**扫描靠反射读注解，创建靠反射 newInstance/invoke**，循环依赖用**三级缓存**解决。
