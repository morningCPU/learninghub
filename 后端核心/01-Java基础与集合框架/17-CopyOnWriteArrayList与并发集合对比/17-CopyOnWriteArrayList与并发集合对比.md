# 17-CopyOnWriteArrayList与并发集合对比  
  
## 一、学什么  
  
> 1. 写时复制原理  
> 2. 读多写少场景  
> 3. 弱一致性  
  
  
  
## 二、做什么  
  
### 2.1 基础知识  
  
线程安全的List  
写时复制(Copy-On-Write COW)  
读读不互斥，读写不互斥，写写互斥  
  
### 2.2 核心成员变量  
  
```java  
//互斥锁，所有修改操作加锁  
final transient ReetrantLock lock = new ReetrantLock();  
  
//底层数组，volatile保证引用的内存可见性  
private transient volatile Object[] array;  
  
//获取数组  
final Object[] getArray(){  
    return array;  
}  
  
//设置数组引用(原子替换)  
final void setArray(Object[] a){  
    array = a;  
}  
```  
  
### 2.3 add  
`加锁 -> 复制全新数组 -> 在副本上面修改 -> 替换数组引用 -> 解锁`  
  
在副本上面修改是为了不妨碍读，在写的过程中的读会读取旧数组中的数据  
  
### 2.4 get  
完全不加锁  
如果在是在add的过程中进行get，那么读取的就是旧数组的数据，所以是弱一致性  
**为什么这样线程安全？**  
写操作不会改动旧数据，旧数据是只读快照，读线程不会读到正在修改一半的数组(脏数据)  
  
### 2.5 弱一致性迭代器  
在创建迭代器的瞬间，获取当前array的引用作为快照数组，迭代器全程遍历的是这个快照数组  
后续的写操作都是在新数组上进行的，不会影响前面的快照  
  
### 2.6 优缺点分析  
**(1) 优点**  
  
> 1. 读操作无锁，读性能强，高并发读场景优势巨大  
> 2. 读写不阻塞，读线程不会被写线程阻塞  
> 3. 迭代安全  
> 4. 线程安全  
  
**(2) 缺点**  
  
> 1. 写的代价高，每次写都要全量拷贝数组  
> 2. 内存占用高，写操作瞬间内存同时存在旧数组和新数组两份数据  
> 3. 只能保证最终一致性，不能保证实时一致性  
> 4. 复合操作不保证原子性  
  
### 2.7 适合场景  
  
**(1) 适合**  
读多写少，数据量不大，允许短暂读到旧数据  
**(2) 不适合**  
写操作频繁，数据量大，要求强一致性  
  
  
  
## 三、实践  
  
**1. add 的加锁/拷贝/setArray 细节与 get 无锁的原因**  
  
**add 流程**  
add 方法首先获取 ReentrantLock 锁，保证同一时刻只有一个线程执行写操作（写写互斥）。拿到锁后获取当前底层旧数组，调用 Arrays.copyOf 拷贝出全新数组容器，在新数组上完成元素新增，再通过 setArray 用 volatile 语义替换底层 array 的引用，最后在 finally 块解锁。 写操作必须加锁：防止并发写时，多个线程同时拷贝生成多个新数组，造成数据丢失。  
  
**get 无锁的原因**  
COW 核心是写时复制，已经发布的旧数组永远不会原地修改。get 直接读取 volatile 修饰的 array 引用，拿到当前数组快照取值。 写线程修改的是拷贝出来的新数组，不会改动旧数组。读线程拿到旧数组引用，读到的一定是完整、不会被篡改的数据，不会出现半写脏数据，因此读不需要加锁。 volatile 只保证 array**引用的内存可见性**，不保证数组内部元素的可见性。  
  
写加锁防止并发写冲突，拷贝数组做到不修改原数组；读无锁，因为读访问的数组快照是只读的，不会被写线程改动  
  
**2. CopyOnWriteArrayList和Collections.synchronizedList的区别**  
  
**(1) 锁策略**  
`CopyOnWriteArrayList`：写操作加 ReentrantLock，读操作无锁。读读、读写都不阻塞；只有写写互斥。`Collections.synchronizedList`：所有方法都用 synchronized 加锁，读写全部互斥，读和读之间也互相阻塞。  
**(2) 写机制**  
COW：写时拷贝整个数组，在副本修改后替换引用，写开销 O (n)，代价大。  
synchronizedList：直接在原数组原地修改，写开销小，锁竞争是主要开销。  
**(3) 迭代器**  
COW：弱一致快照迭代器，创建迭代器时拿到数组引用快照；不会抛 ConcurrentModificationException，但是遍历看不到迭代创建后的新增 / 删除数据。  
synchronizedList：fail-fast 快速失败迭代器，遍历期间其他线程修改集合，直接抛出并发修改异常。  
**(4) 适用场景**  
CopyOnWriteArrayList：读多写少（配置、白名单），允许读到短暂旧数据。  
Collections.synchronizedList：读写频率比较均衡、写操作比较多的场景。  
**(5) 内存与 GC**  
COW：每次写产生新数组，瞬时内存占用翻倍，大数据量写容易 GC 压力大。  
synchronizedList：没有数组拷贝，内存开销稳定。
